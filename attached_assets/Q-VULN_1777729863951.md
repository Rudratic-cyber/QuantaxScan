## 1. Vision & Problem Statement

### The One-Liner
> *"Quantum computers break RSA in 2026–2030. Q-Vuln finds every line of code that dies on Q-Day — and replaces it before you do."*

### The Problem
Cryptographic algorithms that secure virtually every application on the internet — RSA, ECDSA, ECC, DH — are mathematically vulnerable to Shor's algorithm running on a sufficiently powerful quantum computer. NIST finalized post-quantum cryptography (PQC) standards in 2024. The U.S. government issued executive orders mandating PQC migration. Every Fortune 500 company has a "PQC migration task force" right now.

The gap: **no tool exists** that lets a developer paste a GitHub URL and instantly understand exactly what breaks on Q-Day and how to fix it.

### The Solution
Q-Vuln is an AI-powered, VS Code-style IDE agent platform that:
- Accepts any GitHub repository or ZIP-uploaded project
- Scans every source file in real time, line by line
- Maps every cryptographic vulnerability to its NIST-approved PQC replacement
- Generates a full risk report, PR-ready fixes, and a compliance-ready audit document
- Builds collective knowledge through a community scan mode

### The Narrative
*"For 10 years, Replit helped you ship. Q-Vuln helps you survive the next 10."*

## 8. Agent Modes

Users select their agent mode before initiating a scan. The mode is displayed persistently in the chat panel header.

### Mode 1: Scan Only
**What it does:** Reads the entire codebase, identifies all cryptographic vulnerabilities, and produces a report. Makes zero changes.

**Best for:** Audits, initial assessments, compliance checks where no modification is desired.

**Agent behavior:** Silent scan → full report delivered on completion. Chat panel shows real-time log of findings but no interactive dialogue.

---

### Mode 2: Interactive
**What it does:** Scans the codebase, then pauses at each vulnerability and asks the user whether to apply the fix, skip it, or flag it for later.

**Best for:** Developers who want full control over every change and want to understand each fix before it's applied.

**Agent behavior:**
```
Agent: "Found RSA-2048 in /src/auth/keypair.py (line 42).
        NIST replacement: ML-KEM-768.
        Estimated effort: ~2 hrs.
        Apply fix? [Yes] [Skip] [Explain More]"
```

---

### Mode 3: Proactive
**What it does:** Scans the entire codebase and automatically applies all NIST-recommended replacements without waiting for user input.

**Best for:** Teams that want the fastest possible migration path and trust the agent's judgment.

**Agent behavior:** Full autonomous scan and fix. Produces a complete diff and changelog. User reviews the output after completion.

**Safety guardrails:**
- Proactive mode never modifies `/tests` or `/vendor` directories
- Creates a full diff summary before finalizing — user can reject individual changes
- All changes are staged (never committed without explicit user action)

---

### Mode 4: Community Scan
**What it does:** Scans the codebase (same as Scan Only) but additionally extracts anonymized vulnerability patterns and contributes them to the Community Hub knowledge base.

**Best for:** Open-source maintainers and developers who want to give back to the Q-Vuln community.

**Agent behavior:** Same as Scan Only, plus:
- Extracts pattern signatures (not code, not identifying info)
- Posts aggregate findings to Community Hub (e.g., "Django apps commonly use MD5 for password hashing in settings.py")
- Earns the user "Contributor" badges and community reputation points

**Privacy:** No raw code is ever sent to the community. Only abstracted vulnerability pattern metadata.

## 9. Real-Time Scanning Engine

### Scanning Scope
The agent scans all files matching these extensions: `.py`, `.js`, `.ts`, `.go`, `.java`, `.kt`, `.rb`, `.php`, `.rs`, `.cpp`, `.c`, `.cs`

The following directories are **always excluded**: `/test`, `/tests`, `/vendor`, `/node_modules`, `/__pycache__`, `/.git`, `/dist`, `/build`

### Vulnerability Targets

The scanner uses AST-level analysis to detect the following:

| Algorithm/Pattern | Detection Target |
|---|---|
| RSA | `RSA`, `Crypto.PublicKey.RSA`, `java.security.KeyPairGenerator("RSA")`, `crypto.generateKeyPair('rsa')` |
| ECDSA | `ECDSA`, `EC`, `secp256k1`, `prime256v1`, `elliptic.P256()` |
| ECDH | `ECDH`, `crypto.createECDH` |
| DSA | `DSA`, `java.security.KeyPairGenerator("DSA")` |
| DH (Diffie-Hellman) | `DH`, `DHParameterSpec`, `crypto.getDiffieHellman` |
| MD5 | `md5`, `hashlib.md5`, `crypto.createHash('md5')` |
| SHA-1 | `sha1`, `hashlib.sha1`, `SHA1`, `MessageDigest.getInstance("SHA-1")` |
| AES-ECB | `AES/ECB`, `Cipher.getInstance("AES/ECB")`, `AES-ECB` |

### Line-by-Line Visual Feedback

As the agent reads the codebase, the user sees the scanning cursor progress through lines in the editor. After analysis, each line is categorized:

| Color | Label | Meaning |
|---|---|---|
| 🔴 **Red** | Critical | Quantum-vulnerable algorithm — breaks on Q-Day. Immediate action required. |
| 🟡 **Yellow** | Mid Alert | Deprecated/weak algorithm not directly broken by Shor's algorithm but not PQC-safe (e.g., MD5, SHA-1, AES-ECB) |
| 🟢 **Green** | Good | No cryptographic concern detected. Quantum-safe. |

Lines without any cryptographic content are left unstyled (neutral/default).

### Scan Progress Indicators
- **Progress bar** in the chat panel header: "Scanning 2,847 of 10,432 lines..."
- **File counter**: "File 14 of 67: /src/payments/stripe_helper.py"
- **Live finding counter**: "🔴 12 critical | 🟡 7 alerts | 🟢 341 clean"
- A subtle glowing "pulse" animation on the current line being read

## 10. PQC Vulnerability Mapping

All vulnerabilities are mapped to NIST-finalized PQC standards (August 2024):

### Primary Replacements

| Vulnerable Algorithm | NIST PQC Replacement | Standard | Use Case |
|---|---|---|---|
| RSA (Key Encapsulation) | **ML-KEM** (CRYSTALS-Kyber) | FIPS 203 | Key exchange, TLS |
| RSA (Signatures) | **ML-DSA** (CRYSTALS-Dilithium) | FIPS 204 | Digital signatures |
| ECDSA | **ML-DSA** (CRYSTALS-Dilithium) | FIPS 204 | Digital signatures |
| ECDH / DH | **ML-KEM** (CRYSTALS-Kyber) | FIPS 203 | Key agreement |
| DSA | **SLH-DSA** (SPHINCS+) | FIPS 205 | Stateless hash-based signatures |
| MD5 | **SHA-256 / SHA-3** | Existing NIST | Hashing (not quantum-specific but weak) |
| SHA-1 | **SHA-256 / SHA-3** | Existing NIST | Hashing |
| AES-ECB | **AES-GCM / AES-CBC** | Existing NIST | Symmetric (ECB is structurally weak) |

### Effort Estimation Model

Each flagged line is assigned an effort estimate based on complexity:

| Scenario | Estimated Effort |
|---|---|
| Import swap only (e.g., library upgrade) | 0.5 – 1 hr |
| Function-level refactor with same interface | 1 – 4 hrs |
| Algorithm change requiring protocol updates | 4 – 16 hrs |
| Full key infrastructure replacement | 16 – 80 hrs |

These are displayed per finding and aggregated in the dashboard.

## 11. Scan Results & Explanation Layer

After the full scan completes, Q-Vuln presents a structured explanation before showing the dashboard.

### Explanation View

This is a narrative, human-readable summary rendered as a full-screen overlay or dedicated tab. It contains:

**1. Executive Summary**
Plain-English paragraph: "We scanned 10,432 lines across 67 files. We found 47 quantum-critical vulnerabilities and 12 weaker-crypto alerts. Your highest-risk area is `/src/auth/` where RSA-2048 is used for key generation in 6 locations."

**2. Vulnerability Breakdown by File**
Collapsible list: each file with its findings, the vulnerable lines, and the recommended replacement.

**3. What Changed (Proactive / Interactive modes)**
A unified diff view showing every applied or proposed change, grouped by file.

**4. Relevant Documentation**
Auto-linked resources:
- NIST FIPS 203 / 204 / 205 specification pages
- Migration guide for detected library (e.g., "Migrating from `cryptography` Python library to PQC-ready alternatives")
- CISA Post-Quantum Cryptography Initiative resources
- CVE entries for known exploits of detected algorithms

**5. Compliance Notes**
One-paragraph summary of which regulatory frameworks (NIST, CISA, NSA CNSA 2.0) are relevant to the findings and what level of urgency they assign.

## 14. File Management

### Import Methods

| Method | Auth Required | Max Size |
|---|---|---|
| GitHub OAuth Repo Select | GitHub sign-in | Up to 500MB repos |
| ZIP Upload | None | 100MB per ZIP |

### ZIP Handling
1. User uploads `.zip` file from the onboarding screen or project creation modal
2. App unzips the archive server-side into the sandboxed project environment
3. File tree populates in the IDE immediately
4. Original ZIP is retained for download

### Download / Export
After any scan (any mode), users can:
- **Download modified project** as a ZIP (includes all agent-applied changes)
- **Download Q-VULN.md** — the standalone audit report (see Section 17)
- **Copy PR diff** — the complete diff formatted as a GitHub Pull Request body

### File Persistence
- Authenticated users: Projects persist across sessions in Q-Vuln storage
- Guest users: Session-only; files are purged after browser tab closes (warned at upload)

## 18. Risk & Mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| **Live scan of large repos is slow** | High | Pre-run reports on 3 demo repos (React, Node, Postgres) as fallback. Show streaming progress to mask latency. |
| **False positives in crypto detection** | Medium | AST-based detection (not regex) reduces false positives. "Ignore" option per finding. |
| **User doesn't trust automated fixes** | Medium | Interactive mode defaults — agent asks before changing anything. Full diff always shown before commit. |
| **Guest users frustrated by limitations** | Medium | Clear messaging at onboarding. One-click upgrade to email/GitHub. |
| **Community Hub spam/low-quality posts** | Low-Medium | Moderation queue for new users. Upvote/downvote system. Auto-filtering by Community Scan quality score. |
| **PQC library support varies by language** | High | Initial release focuses on Python + JavaScript. Go and Java in v1.1. |
